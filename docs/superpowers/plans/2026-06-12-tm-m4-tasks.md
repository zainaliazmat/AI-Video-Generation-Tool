**Goal:** Extend `/templates` into the two-tab (Installed | Marketplace) marketplace surface per the approved wireframe: tabs+search+kind-pills with live counts, ghost "Install from .zip" + whole-page drag overlay, in-card stage checklist (no percent bar), update triad, full state matrix, marketplace drawer with the one tinted Install, drawer danger-zone uninstall, derived uncommitted badge, use-it chip, responsive + a11y (focus rings on new AND existing controls). Backed by SSE install/uninstall/state/index routes that drive the M2 engine with keep-alive-on-disconnect.

**Visual reference (open BOTH, every UI task):**
- `~/.gstack/projects/zainaliazmat-AI-Video-Generation-Tool/designs/templates-marketplace-20260612/wireframe.html`
- `~/.gstack/projects/zainaliazmat-AI-Video-Generation-Tool/designs/templates-marketplace-20260612/approved.json`

**Architecture:** Routes are thin: they call the M2 engine (`install`/`installFromMarketplace`/`uninstall`/`installedState`) and the M3 seam (`LocalFolderSource`). The engine gains ONE additive hook — an optional `onStage(name)` callback fired as each pipeline stage begins — so the route can stream the §16.3 stage checklist over SSE without the engine knowing about HTTP. **Keep-alive-on-disconnect (§16.15-1/§16.3):** unlike the render donor (which kills the child on client disconnect), the install route does NOT abort on disconnect — `install()` runs to completion/rollback server-side (it already does; M2 has no client coupling), and the UI re-syncs on return via `GET /api/templates/state`. We do NOT build live-stream re-attach (a server-side event buffer keyed by install id) — server-side completion + state re-sync is the spec's stated contract ("revisiting re-syncs from the single-flight lock/state"); note this in the route comment.

**Installed-ness is DERIVED, never asserted (§16.6):** the page server-payload carries one installed-ids set + the marketplace index; tabs, counts, drawer, badges all derive from it; terminal SSE events fire `router.refresh()` (the page is `force-dynamic`). No component-local "installed" boolean.

**Tech:** Next.js App Router (cwd = `preview/`); Node-runtime SSE routes (donor `preview/app/api/render/route.ts:66-161`); the M2 installer (`templates/scripts/install.mjs`) and M3 seam (`preview/lib/marketplace.ts`) imported server-side; React client components reusing `Badge`/`Button`/`Eyebrow`/`.glass`/`.content-card`/`--glass-border-active`; framer-motion (already a dep); vitest (added to preview for the pure derive/filter logic — the visual proof is the §16.14 browser gate). **Where this plan and §16 conflict, §16 wins.**

**Engine note (M4-branch touch to `templates/scripts/install.mjs`):** add `opts.onStage?(stageName)` fired at the START of each stage in `install()`/`installFromMarketplace()`/`uninstall()`. Stage names (the SSE contract): `'validating'`, `'typecheck'`, `'assets'`, `'register'`, `'rendering-preview'`, `'done'`; on failure the route uses the caught `InstallError.stage`. This is additive (default no-op) and must not change any existing test (all current calls omit it).

The pure module (the §16.6 "derived, never asserted" core — testable):
```ts
export type Tab = 'installed' | 'marketplace';
export interface UnifiedItem {
  id: string; name: string; kind: string; author: string; version: string;
  description?: string; tags?: string[]; license?: string;
  source: 'installed' | 'catalog';
  installed: boolean;             // derived from the installed-ids set
  catalogVersion?: string;        // version available in the catalog (for the update triad)
  uncommitted?: boolean;
  mp4?: string | null; poster?: string | null;
}
export interface DeriveInput {
  installed: UnifiedItem[]; catalog: UnifiedItem[];
  installedIds: Set<string>; tab: Tab; query: string; kind: string | 'all';
}
export interface DeriveOutput {
  items: UnifiedItem[];          // the active tab, filtered by query+kind
  installedCount: number;        // matches in installed tab for the current query
  marketplaceCount: number;      // matches in marketplace tab for the current query
  kinds: string[];               // kind facets present in the active tab
  zeroResult: { active: boolean; otherTabMatches: number };  // §16.2 cross-tab
}
export function deriveView(input: DeriveInput): DeriveOutput;
```
- `installed` flag on a catalog item = `installedIds.has(item.id)`. Update-available = catalog item whose `catalogVersion` > installed version (semver) — compute a per-item `updateAvailable` (add to UnifiedItem or DeriveOutput). Search matches name/id/tags/kind/author (case-insensitive substring). Counts are per-tab matches for the SAME query (so both tab labels update — §16.2). zeroResult.otherTabMatches = matches in the inactive tab (for the cross-link).
