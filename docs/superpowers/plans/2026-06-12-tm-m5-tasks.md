# M5 — Authoring Kit: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`).

**Goal:** Make a third party able to build a conforming template without reading our source: `docs/TEMPLATE-AUTHORING.md` (§9.1 normative outline + frozen-dependency section), the doctor **import-lint** (frozen import surface §15.6, named on violation), the `new-template` scaffold (passes doctor untouched — CI test), and `pack-template` (doctor-first, refuses failing templates).

**Architecture:** The import-lint is a new validation stage (`_stageImports`) in `install-stages.mjs`, so it runs in EVERY `install()` AND `doctor()` — "doctor-clean == installable" stays true. Frozen bare-import allowlist = `react`, `react-dom`, `remotion`, `@remotion/transitions`, `zod` (§15.6); RELATIVE imports (`./…`, `../sdk`) are allowed — they're the package-local files or the SDK type contract every template imports (the 3 M3 seeds already import `../sdk` + `./schema`). The scaffold produces a working `templates/<id>/` folder that passes doctor with zero edits — the standard's executable example. `pack-template` runs doctor first and only zips a passing template. **Where this and the spec conflict, the spec (§9/§15.6) wins.**

**Tech:** Node `.mjs` (`new-template.mjs` new; `pack-template`/import-lint inside the installer); the M2 `doctor()` is the gate; `adm-zip` for packing; vitest in the templates suite. Markdown for the doc.

### Task 2: `docs/TEMPLATE-AUTHORING.md` (§9.1 normative)

**Files:** Create `docs/TEMPLATE-AUTHORING.md`.

Write the normative doc per the §9.1 outline (read §9.1 + §15.6 in template-marketplace-plan.md). Sections:
1. **Anatomy & naming** — folder layout (§4.1: manifest.json + Component.tsx/presentation.tsx + optional schema.ts + optional assets/ with CREDITS.json); id rules `^[a-z][a-z0-9-]{1,40}$`; folder name == id.
2. **The manifest, field by field** — every envelope field incl. when `rendersOwnText` must be true (your component draws the narration text itself; lying double-prints captions) and what `consumes` means (a content capability the recipe routes generically; don't invent capabilities). The v1.1 fields (description/tags/license/homepage/assets); license required for non-core authors.
3. **Props: author zod once** — schema.ts exports `schema`; `z.infer` types your component; NEVER hand-edit `inputSchema` (gen-manifests owns it; the installer diffs it at stage 5); sampleProps must satisfy your own schema (it renders your gallery preview).
4. **The component contract** (normative from sdk.ts): receive `TemplateProps` {data, theme, timing, assets, wordTimings?, itemTimings?}; **style from `theme` tokens only** (no hardcoded colors/fonts — survive any palette); **animate with `useCurrentFrame()` strictly within `timing.durationInFrames`** — you paint a span, never define one; **deterministic & pure** (no network, no Date.now, no unseeded randomness); **fail closed on render-derived timings** (absent/empty wordTimings/itemTimings → your non-synced entrance); **assets only via the `assets` prop** (relocatable installs; declare them in the manifest; ship CREDITS.json); respect `durationFrames` honestly; transitions export a presentation FACTORY from presentation.tsx on remotion primitives.
5. **Dependencies (the frozen import surface, §15.6)** — name the rule explicitly: v1 templates may import ONLY `react`, `react-dom`, `remotion`, `@remotion/transitions`, and `zod` (types). Relative imports (`./…`, `../sdk` for the type contract) are allowed. Anything else fails doctor's import-lint, which names the rule. Real dependency support = the npm-package trajectory (M6). (Cite enumeration's lucide-react needing a manual remotion.config webpack alias as exactly the wall a third party must not hit blind.)
6. **Versioning** — semver: breaking inputSchema change → major; visual-only → minor/patch. apiVersion belongs to the SDK, not you.
7. **Validate & package** — `doctor` until clean (it IS the install gate, byte-for-byte), then `pack-template` → the zip you drag into any Studio or submit to the marketplace. Show the commands.

Keep it concrete and example-driven; reference the scaffold (Task 3) as the executable example. No placeholders.

- [ ] **Step 1:** write the doc. **Step 2:** Commit — `git add docs/TEMPLATE-AUTHORING.md && git commit -m "docs(authoring): TEMPLATE-AUTHORING.md — normative standard + frozen dependencies — §9.1/§15.6"`
